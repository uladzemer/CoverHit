# Carpet scans and stock-photo drop-in

Gameplay uses only photographs of actual rugs. The old pattern renderer and its tests are removed. Painting-derived tapestries 11-13 are excluded; their generated framed outputs are removed. Raw painting sources remain for provenance. A failed scan is retried twice, then another museum/stock scan is loaded. If all scans fail, loading stops with a retry message. No drawing is substituted.

Run `npm run carpets:new` after placing licensed JPG/PNG photographs in `assets-src/carpets/envato/`. Filenames must contain the seven-character Envato item ID, e.g. `B7PV8QR.jpg`. The command obtains a convex-hull prior, then refines it through the background/texture segmentation and robust line fitting in `scripts/carpet-cut/`. It creates idempotent draft config entries and corner overlays in `assets-src/carpets/_debug/`. Draft titles and corners can be edited directly in `scripts/carpets.config.json`; set `easy: true` on a bright, easy stock rug to make it first. Otherwise bright, light Kazak 09 stays first, followed by stock photos, then the remaining museum scans.

Run `npm run carpets` to rectify and crop, or `npm run build` which also rebuilds the manifest. Corners are source pixel coordinates ordered top-left, top-right, bottom-right, bottom-left. A destination-to-source homography corrects rotation and perspective; the build samples at 1.5× output resolution and downsamples with Lanczos3. Adaptive inward cuts remove background before a thin 0.4% darker/desaturated woven edge is baked from the rug's own pixels. The cut is validated before polish and again after decoding the WebP. No pattern is repainted or stretched; manifest aspect is measured from the final image pixels. See the 2026-10-10 cut notes below for overrides and limits.

Factory physical height comes from the carpet type, width is exactly `height * aspect`. The grid uses uniform intervals along each image axis and approximates square cells within a 1,800-node budget. The chosen folding axis has an even interval count. The flat rest links preserve the full physical dimensions through the crown; UVs remain continuous over the middle fold, without squeezing or repeating any image rows. Map repeat is (1,1), offset (0,0), rotation 0, clamp-to-edge.

Fold rule (`foldLayout` in assets.js): fold crosswise over the bar, with the short dimension along the bar and half the long dimension hanging on either side. Portrait scans fold at v=0.5; landscape scans at u=0.5. The two short material ends become the lower front and back edges. The yard fits the largest selected span with 0.3 m clearance at either end. Front panel UVs run from the image middle at the crown to an image end at the bottom; the other half hangs equally behind. Both panels render the scanned face outward.

Licensed stock originals, processed `public/carpets/envato-*` files, debug images, and individually named Envato QA screenshots are ignored. The config contains metadata and corners only. Missing stock originals are skipped on build, stale corresponding processed files are removed, and the manifest falls back to the museum rotation. Credits say `Envato Elements, item <ID>` and `Envato Elements (personal)`. Do not redistribute locally generated licensed assets.

Tests cover pixel-to-factory aspect (0.5% maximum; current results are exact), near-square cell spacing, uniform structural links across the fold, scan retry/failover, the absence of pattern imports, draft import/idempotence, perspective sampling, and missing optional stock originals. Detector regression tests copy scans 03/04 to a temporary folder and require all detected corner coordinates within 3% of the independently reviewed source coordinates.

Browser QA: run Vite, then `node scripts/verify-carpets.mjs` (local Playwright and Chrome). Evidence and per-image review notes are in `docs/qa/carpets/README.md`.

The currently supplied stock set is reviewed: B7PV8QR is first/easy, 6325SWE and EPRJ58X retain their photographed frame, and T834FYR removes its studio backdrop. RBFEDY2 now uses four reviewed corners on the outermost complete inner frame: its source already clips the original outer motif border on the left/top. The incomplete outer motif bands and striped end extension are excluded. Fragments 2K7L5EB/QSMGCAP are disabled. Museum 03/04 exclude plain kilim end extensions, and 02 excludes the remaining lower display-mat sliver.

The committed `public/carpets/manifest.json` contains museum scans only. The pipeline writes available stock entries to gitignored `manifest.local.json` (and removes it when none are available). Runtime merges this optional file; a 404 is silent, so clean checkouts rotate 09, 03, 01, 06, 02, 04, 07, 05, 08, 10 without stock requests or stock credits. Failed scans advance forward from the current rotation position. Exhausted scans show a persistent Russian loading-error toast with a retry button.

The Vite build removes `envato-*` images and `manifest.local.json` from `dist/carpets` by default, even if licensed files exist locally. Set `COVERHIT_INCLUDE_STOCK=1` only for the owner's personal local build. This opt-in build contains licensed assets and must not be redistributed.

## Clean cuts — 2026-10-10

The current rotation contains nine museum rugs and five optional local stock rugs. Museum 02 is now disabled: its irregular worn boundary and beige display mat cannot pass the literal ΔE < 12 colour criterion without deleting intact weaving. Stock fragments 2K7L5EB/QSMGCAP remain disabled. Older rotation lists above describe the earlier set; 02 is omitted automatically by the unchanged runtime manifest loader.

`scripts/carpet-cut/segment.mjs` clusters smooth photo-ring samples in CIE Lab and requires cluster support immediately outside the reviewed rug, excluding unrelated photographic frames. Local texture energy supplements colour separation. Morphological close/open, largest component selection and hole filling give a foreground mask. Boundary transitions are searched at half-pixel positions perpendicular to each prior side; central colour gradients score the transitions. Deterministic RANSAC and trimmed total least squares reject fringe/noise. Convexity, perspective corner angles, source bounds and drift from the prior gate the fitted quad. Source corners may be keystoned; only the rectified output is required to have 90° corners.

`cut.manualCorners` overrides fitting while leaving the original `corners` as fallback priors. 05/06/07/08/09/10 use reviewed inward envelopes; 03/04 keep reviewed woven ends while fitting the long sides. T834FYR retains its already-safe manual studio crop. Full-bleed stock has no visible background to estimate; its zero leakage means no known surround, not proof of an original whole-rug outline. RBFEDY2 still retains only the complete inner frame documented above.

`finish.mjs` inspects every edge pixel and searches each side independently, including corner checks. Its preferred inset is 0.3–1.2%. Explicit manual envelopes and subsequent symmetry/aspect cuts exceed that target in some places; the largest original bows cannot be removed inside a 1.2% strip. `symmetry.mjs` balances only independently reviewed symmetric opposing borders. Original asymmetric pairs are reported, not forced to equality. Paired inward aspect cuts keep the existing cloth grid's square-cell tolerance and prevent any per-rug Ammo node increase. These crops remove pixels; they do not rescale the pattern to invent a border.

Output remains WebP plus thumbnail and the unchanged museum/local manifest schema. `public/carpets/cuts.json` is diagnostic metadata only, not read by gameplay. Every shipped rug has 0.0% leakage in the outer four pixels and ≤0.5% in the next eight, before edge polish and after final decoding. All reviewed symmetric pairs measure within 3% on decoded output. The reported ≤0.25% after straightness is the trimmed boundary line-fit residual; it is **not** a claim that the new straight inward cut agrees with every point of a bowed original boundary. Full untrimmed agreement cannot meet that bound on these sources. Rectified corner error is 0°.

Reproduce diagnosis before modifying an existing build with `node scripts/carpet-cut/diagnose.mjs` (overwrites the before baseline). Rebuild with `npm run carpets`, then run `node scripts/audit-carpets.mjs` for before/after sheets and [the per-rug metrics and decisions](qa/cuts/summary.md). Each sheet has four positions on all four sides, 6% deep, enlarged 3×. Disabled after sheets are labelled diagnostic only. Optional stock PNGs/JPGs are ignored by `docs/qa/cuts/envato-*`; no new images were downloaded and the existing source provenance applies.

`node scripts/carpet-cut/verify.mjs` runs the production build, compares SHA-256 hashes with the preceding build, checks the 60-second carpet limit, asset budget and per-rug Ammo grid counts, and records [verification.json](qa/cuts/verification.json). Tests cover noisy/fringed line fitting, wall/floor clustering, morphology, keystoned rectification, deterministic edge polish, actual decoded WebP leakage and border symmetry, optional-stock absence, and unchanged/decreased grid counts. The final assets use quality 85; the encoder checks quality 90/95 and then lossless if compression introduces any failing edge pixel.


Middle-fold QA and actual browser combo intervals: [docs/qa/fold/README.md](qa/fold/README.md). Reproduce with Vite running and `node scripts/verify-fold.mjs` (local Playwright and Chrome).

Border measurements and fringe QA: [docs/qa/fringe/README.md](qa/fringe/README.md). Run `node scripts/audit-carpets.mjs` to measure every present source against independently reviewed field landmarks in `scripts/carpets.audit.json`. RGB edge profiles measure the same nested frame before/after; missing sources skip, disabled fragments are marked unframed. RBFEDY2's complete inner frame is within 2% for both opposing pairs. Other original designs have hand weaving, wear, bowed edges or unequal photographed borders; tests preserve their reviewed widths instead of trimming intact motifs to force equality.

`foldLayout` now always folds crosswise: the short side spans the bar and the long axis is halved. Procedural fringe attaches to both short material ends, so those ends hang below both halves. Wool uses approximately 8–10 cm strands, palas/runner approximately 6–7 cm, tapestry none. One InstancedMesh contains low-poly cream wool bunches tinted from the scan's light end-border pixels. Roots interpolate actual edge nodes; damped spring motion responds to root velocity, wind, and hits near the edge. Fringe creates no Ammo bodies or links and casts shadows. During throws it continues following the real hem nodes; strands whose segments would cross the pipe deflect radially outward instead of shrinking out. See docs/qa/flipwave for hand-throw contact sheets and measurements.
